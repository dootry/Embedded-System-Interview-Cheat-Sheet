## 二、C 语言 ★★★

### Q04 · volatile 的作用与使用场景

**答案**

告诉编译器：不要对该变量做优化，每次读取都必须从内存 / 寄存器真实读取，不要缓存到寄存器。

适用场景：

- 寄存器映射（外设寄存器）
- 中断服务函数修改的全局变量
- 多任务共享变量（RTOS 下）

> **追问陷阱**：volatile 不能保证原子性，**不能替代互斥锁**。这句话一定要主动补上——只答到"防止优化"是及格，补上这句才是满分。

### Q05 · static 的作用（从作用域、生命周期两个维度答）

**答案**

1. **修饰局部变量**：生命周期变成全局（程序启动时分配，直到程序结束），作用域仍在函数内部；只初始化一次。缺点：函数不可重入。
2. **修饰全局变量**：作用域限制在当前 `.c` 文件，其他文件不能 `extern` 引用。
3. **修饰函数**：函数仅本文件可见，外部无法调用。

> **答题技巧**：这题的关键是"两个维度"——面试官问的是作用域和生命周期，不是让你罗列三种用法。先说维度，再逐条填。

### Q06 · const 和 #define 的区别

**答案**

1. `const` 是变量，有类型，编译期做类型检查；`#define` 是预处理宏，纯文本替换，无类型。
2. `const` 占用内存（通常放只读段）；`#define` 不占内存。
3. `const` 可作函数形参做保护；宏容易出现运算符优先级 bug。
4. `const` 在编译阶段处理；`#define` 在预处理阶段替换。

> **补充**：宏的优先级坑可以举一例 —— `#define SQ(x) x*x`，`SQ(1+2)` 展开成 `1+2*1+2 = 5` 而不是 9。加括号写成 `((x)*(x))` 才对。面试官爱听这种具体例子。

### Q07 · 结构体对齐原理，手算结构体大小

```c
struct A {
    char *a;
    char  b;
    int  *c;
};
```

**32 位系统**（指针 4 字节）

| 成员        | 大小      | 偏移 | 说明                    |
| --------- | ------- | -- | --------------------- |
| `char *a` | 4B      | 0  | —                     |
| `char b`  | 1B      | 4  | 后补 3B 对齐到 4 的倍数       |
| `int *c`  | 4B      | 8  | —                     |
| **合计**    | **12B** |    | 最大成员 4B，12 是 4 的整数倍 ✓ |

**对齐规则**（要能原句背出来）

1. 每个成员对齐到自身大小的整数倍；
2. 结构体整体大小是最大成员大小的整数倍。

> **补充 · 高频陷阱**：同样这段代码在 **64 位系统**下是 24 字节（`8 + 1(+7) + 8`）。被问"换个平台呢"要立刻答出，并点明指针宽度变了。另外可以主动提 `#pragma pack(1)` 可以取消对齐，但会牺牲访问效率。

### Q08 · malloc 和 realloc 的区别

**答案**

- `malloc(size)`：申请一块全新堆内存，返回首地址，内容随机。
- `realloc(ptr, new_size)`：对已 malloc 出来的内存扩容 / 缩容。
  1. 原有内存后方空间足够 → 原地扩容，返回原地址；
  2. 后方不足 → 开辟新内存，拷贝旧数据，释放旧内存，返回新地址；
  3. `ptr = NULL` 时等价于 `malloc`；`new_size = 0` 时等价于 `free`。

**必须点出的坑**：`realloc` 一定要判断返回值，**不要直接写 `ptr = realloc(ptr, size)`**，失败会丢失原指针造成内存泄漏。

> 正确写法：
>
> ```c
> void *tmp = realloc(ptr, new_size);
> if (tmp != NULL) ptr = tmp;   // 失败时原 ptr 仍有效，可继续使用或释放
> ```

### Q09 · 指针和数组的区别

**答案**

1. **数组名是数组首地址常量，不能修改**；指针是变量，可以改指向。
2. `char arr[] = "abc"`：数组开辟栈内存（可写）；`char *p = "abc"`：`p` 在栈，字符串常量放在**只读段**（写了会段错误）。
3. `sizeof(arr)` 得到数组总长度；`sizeof(p)` 得到指针本身大小（4 或 8）。
4. 数组作为函数参数时会**退化为指针**。

## 三、外设与总线 ★★★

### Q10 · I2C 的信号、时序规则、从机无响应怎么调

**信号**

两根线：`SCL` 时钟线、`SDA` 数据线，**开漏输出，必须外接上拉电阻**。

**时序**

- 起始：SCL 高电平期间，SDA 出现**下降沿**
- 停止：SCL 高电平期间，SDA 出现**上升沿**
- 每字节 8 bit，后面跟 1 位 ACK 应答位
- **SCL 高电平期间 SDA 不能随意变化**（除起始、停止）

**无响应排查（按硬件 → 波形 → 地址 → 复用 → 软件的顺序）**

1. 硬件：上拉电阻是否焊接、供电是否正常、引脚是否短路
2. 示波器 / 逻辑分析仪抓波形，看起始信号有没有出来、地址位对不对
3. 确认从机地址（**7bit / 8bit 区分**，这是最常见的错）
4. 检查引脚复用配置是否正确
5. 软件：SCL / SDA 时序延时是否符合器件规格

> **答题加分**：这题的评分点不在知识点，在**排查顺序**——"先硬件后软件、先波形后代码"。顺序清晰 = 有实战经验。7bit 地址左移一位再补读写位是常见错误，主动说出来。

### Q11 · SPI 的配置步骤与特点

**四根线**：`SCK` 时钟、`MOSI` 主机发、`MISO` 从机发、`CS` 片选。

**配置步骤**

1. 引脚复用配置为 SPI 功能
2. 配置波特率、`CPOL` / `CPHA`（时钟极性 / 相位）
3. 配置数据位宽、高位先行 / 低位先行
4. 使能 SPI 外设，可配置中断 / DMA
5. 通信前拉低 CS，传输完成拉高 CS

**特点**

高速同步串行、全双工；主机控制时钟；**没有 ACK，没有硬件寻址，靠 CS 片选**。

> **补充**：CPOL/CPHA 四种组合就是 SPI Mode 0–3，Mode 0（CPOL=0, CPHA=0，上升沿采样）和 Mode 3 最常用。跟 flash 通信调不通，90% 是模式配错。

### Q12 · UART 的起始位 / 停止位，串口打印乱码怎么 debug

**帧格式**：起始位（**低电平**）+ 数据位 + 校验位（可选）+ 停止位（**高电平**）。

UART 是**异步**串口，没有时钟线，靠双方约定的波特率对齐。

**乱码排查**

1. **波特率不匹配（最常见）**
2. 数据位、校验位、停止位配置不一致
3. 硬件：电平不匹配（3.3V / 5V）、**地线没共地**
4. 干扰，长线缺少屏蔽
5. 时钟源误差过大（内部 RC 振荡器精度不够）

> **追加追问预警**："波特率对、还是乱码" → 往时钟源精度、共地、电平转换芯片方向答。

### Q13 · PWM 的周期与占空比，硬件 PWM 与软件 PWM 的区别

- **周期**：一次完整高低电平的总时间
- **占空比** = 高电平时间 / 周期

|          | 硬件 PWM    | 软件 PWM          |
| -------- | --------- | --------------- |
| 实现       | 定时器硬件自动输出 | CPU 定时器中断里翻转 IO |
| CPU 占用   | 无需持续干预    | 持续占用，通道越多越吃 CPU |
| 精度 / 稳定性 | 高，无抖动     | 差，多通道多任务时容易抖动   |

> 补充：软件 PWM 在做 BLE 协议栈的同时跑，抖动会直接毁掉时序，这也是为什么无线产品几乎必用硬件 PWM。

## 四、RTOS（FreeRTOS）★★★

### Q14 · 10ms 任务被抢占，来不及喂看门狗怎么办

**方案**

1. **喂狗不要全放在 10ms 任务里**，拆到多个地方喂，或单独开一个低优先级看门狗任务
2. 对长时间阻塞的任务做**分片处理**，中途插入喂狗
3. 使用**窗口看门狗**（WWDT）——既防喂太晚，也防喂太早
4. 优化任务优先级，避免高优先级任务长时间独占 CPU

> **答题框架**：这题本质是"实时性与可靠性冲突"，按 ①喂狗点分散 → ②任务拆分 → ③换看门狗类型 → ④调度优化 递进答，显得思路成体系。

### Q15 · 怎么确定任务栈大小够用

1. 阅读函数调用链，预估局部变量深度
2. 用栈水位检测函数 `uxTaskGetStackHighWaterMark()`，看历史最小剩余栈
3. 调试阶段预留余量（一般留 30% 以上）
4. 递归、大数组**不要放栈上**，放全局 / 堆

> **补充**：`uxTaskGetStackHighWaterMark()` 返回的是"历史最小剩余量"，不是当前值——所以必须在跑过最坏场景（比如连续收包）之后再读。

### Q16 · 中断与任务共享数据、多核之间怎么通信

**单核**

- 关中断 / 临界区保护（`taskENTER_CRITICAL()`）
- 简单标志位可以用 `volatile`，但要注意原子性

**多核**

- 邮箱、消息队列、信号量
- 共享内存 + 自旋锁

**core0 / core1 通信典型方式**：共享内存、中断通知、消息队列。

> **补充**：泰凌微部分型号是双核（如 BLE + 应用核分离），这题很可能结合实际芯片架构追问。如果被问"共享内存怎么保证一致性"，答内存屏障 / `__DMB()` + 自旋锁。

## 五、低功耗与 BLE ★★★（泰凌微核心）

### Q17 · MCU 休眠功耗异常，怎么排查

1. 关闭所有未使用外设的时钟
2. **GPIO 配置**：悬空引脚不能浮空，要拉低或拉高
3. 检查 IO 上拉 / 下拉配置、外部漏电
4. 关闭 ADC、SPI、UART 等模块
5. 测休眠电流，**分段断电定位漏电模块**
6. 确认实际进入的休眠模式（stop / standby / deep sleep）

> **加分项**：提一句"先看 datasheet 里该模式的标称电流，建立基准值再分段排除"，比单纯罗列步骤更像做过。  
> **常见真凶**（可主动补）：调试口 SWD 没关、外部上拉电阻在休眠时漏电、LDO 静态电流、未配置的模拟引脚。

### Q18 · 简单介绍一下 BLE

- **BLE = 低功耗蓝牙**，面向短数据包、低占空比的场景
- **GAP**：管**广播、扫描、连接**（设备怎么被发现、怎么连上）
- **GATT**：管**数据怎么组织**——Service / Characteristic / Descriptor
- 核心机制：广播包、连接事件（connection event）、连接间隔
- **特点**：短数据包、快速连接、可长时间休眠省电
- **应用**：遥控器、传感器、灯控

> **补充 · 大概率追问**：
>
> - 广播包最大 31 字节（BLE 4.x），扩展广播 / BLE 5 可到 255
> - 连接间隔（Connection Interval）最小 7.5ms，越小越实时越费电
> - 一个 GATT 服务由多个 Characteristic 组成，每个 Characteristic 有 UUID、权限、值
> - 配对与绑定（pairing / bonding）的区别
>
> BLE 只答这几句够一面，二面大概率深挖协议栈分层（Controller / Host / Profile）。

**Q19 · RTC 的 BCD 码怎么转十进制**

```c
// BCD: 0x23 表示 23
uint8_t bcd_to_dec(uint8_t bcd) {
    return (bcd >> 4) * 10 + (bcd & 0x0F);
}
// 反向
uint8_t dec_to_bcd(uint8_t dec) {
    return ((dec / 10) << 4) | (dec % 10);
}
```

> 补充：DS1302 / PCF8563 / DS3231 这些常用 RTC 芯片的寄存器都是 BCD 格式，读完不转直接打印会看到 "0x23" 这类怪值——这正是面经里点名的考点。

**Q20 · 用 PWM 调节光源亮度的目的是什么**

- 通过改变**占空比**改变 LED 的**平均电流**，从而改变亮度
- 人眼有视觉暂留，只要频率够高（一般 > 100Hz，实际做调光常用 1kHz 以上）就看不到闪烁
- 相比**线性调压 / 串电阻**，PWM 调光时 MOS 管工作在开关状态，**损耗极小、效率高**，不会发热
- 且不改变 LED 的正向电流峰值，**色温偏移小**

## 七、系统与杂题 ★★

### Q21 · 芯片上电后无法运行，怎么排查

按"电 → 复位 → 时钟 → 启动 → 程序"的顺序：

1. **电源**：供电电压是否稳定，有无压降
2. **复位电路**：复位电平是否正常（NRST 是否被拉低）
3. **时钟**：外部晶振是否起振
4. **BOOT 启动引脚**配置是否正确
5. 程序是否**下载成功**（校验一下 flash 内容）
6. 查硬件短路
7. 调试器能否连上、能否进断点

> **答题技巧**：这题和第 17 题一样，评分点是**顺序**。从供电往上逐级排查，不要一上来就说"程序写错了"。

### Q22 · DMA 的作用

直接内存访问：**外设 ↔ 内存之间搬运数据，不需要 CPU 参与拷贝**，减少 CPU 占用，提升传输效率。常用于 SPI、UART、ADC。

> **补充**：可以补一句"DMA 传输期间 CPU 可以去睡眠，这对低功耗产品是双重收益"——把知识点挂到泰凌微的业务上，效果很好。

### Q23 · CAN 总线的仲裁机制

**非破坏性逐位仲裁**。

- 显性位（0）会覆盖隐性位（1）
- ID 越小优先级越高
- 发送时逐位对比：**自己发 1 却收到 0，说明仲裁失败，立刻停止发送转为接收**
- ID 大的节点不会丢数据，只是失去本次仲裁，等下一次总线空闲再发
